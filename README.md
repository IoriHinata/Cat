# Animal Collector

**Animal Collector** — offline-first Android-игра на русском языке: пользователь выбирает или снимает животное, получает локальный результат Mock AI, даёт находке имя и сохраняет уникальную коллекционную карточку. Игровая редкость вычисляется только локальным движком, а не AI.

## Запуск

1. Откройте корневую папку в Android Studio Ladybug или новее.
2. Выберите JDK 17, установите Android SDK Platform 35 и синхронизируйте Gradle.
3. Запустите конфигурацию `app` на устройстве Android 8.0+ (API 26).
4. Для проверок выполните `gradle testDebugUnitTest` (либо используйте Android Studio).

Проект использует Kotlin, Jetpack Compose/Material 3, Navigation-ready single activity, Room, DataStore dependency, Coroutines/StateFlow-compatible data layer, CameraX dependencies и системный Android Photo Picker. Разрешение камеры запрашивается только при нажатии соответствующей кнопки. Gallery picker ограничен двумя импортами в локальный календарный день; состояние счётчика хранится в Room.

## Игровой цикл и данные

* `MockAnimalRecognitionService` полностью работает без ключа: возвращает кошек, собак, сову и лису. `RemoteAnimalRecognitionService` — безопасная точка расширения: без настроенного провайдера не загружает фото и сообщает понятную ошибку.
* Каждая карточка получает UUID; изображение хранится как URI, а карточка — в Room. Модель содержит владельца, фото, распознавание, оценку, редкость, дату, защиту, срок и состояние хранения.
* `RarityScoreCalculator` детерминирован по seed, ограничивает оценку 5…1000 и избегает типовых круглых значений. Изменяемые правила вида/породы/окраса расположены в `RarityRules`.
* Сумка имеет пять слотов каждого ранга. `BagManager`, `SlotPriceCalculator` и `CardExpirationManager` отвечают за хранение, неокруглённые цены и потерю только незакреплённых карточек вне сумки.
* Исследования, достижения и локальная транзакционная state machine вынесены в независимые игровые сервисы. `TradeManager` не позволяет завершить один transactionId дважды.

## Архитектура

Код отделяет domain-модели (`domain`), игровые правила (`game`), распознавание (`ai`), Room-персистентность (`data`) и Compose UI (`ui`). Это позволяет заменить локальные реализации на `OnlineTradeService`, облачный профиль или реальный AI без привязки игровых правил к Bluetooth/Wi‑Fi. Bluetooth и локальная сеть требуют производственных transport-реализаций и пользовательского discovery/подтверждения; в 1.0 намеренно не выполняют небезопасный автоматический обмен.

## Приватность и ограничения 1.0

Фото остаются на устройстве, пока не подключён внешний распознаватель; геолокация не используется. Система не содержит рекламы, платежей или loot boxes. Полноценный CameraX preview/capture, экспорт bitmap-карточки, уведомления, albums/series UI и подтверждённый двухсторонний Bluetooth/Wi‑Fi transport — следующий производственный этап; текущие разделы явно обозначены в интерфейсе как расширяемые, а не имитируют завершённую функцию.

## Тестирование

Unit-тесты покрывают score/rank, цены и недостаток points, дневной лимит, expiration/защиту, XP, идемпотентные достижения и повторное завершение обмена.

## APK через GitHub Actions

После push в ветку `work`/`main`, pull request или ручного запуска workflow **Build Android APK** GitHub Actions запускает unit-тесты, собирает `assembleDebug` на JDK 17 и публикует `animal-collector-debug-apk` как artifact на 14 дней. APK можно скачать на странице **Actions → нужный запуск → Artifacts**.

## Локальный профиль и хранение

В разделе **Ещё → Настройки и резервная копия** создаётся локальный профиль исследователя. Имя сохраняется в DataStore, а все данные карточки — UUID, имя, URI фото, вид, научное название, семейство, порода, окрас, confidence, описание, Wikipedia query, score, редкость, дата и статус — записываются в локальную Room-базу телефона. В приложении нет Google-входа, облачного аккаунта или сетевой передачи карточек.

Важно: стандарт Android удаляет данные приложения при его удалении. Поэтому локальное хранение гарантирует сохранность между перезапусками и обновлениями приложения, но не может восстановить данные после uninstall без отдельной экспортной копии. Это поведение явно показывается на экране локального профиля.
